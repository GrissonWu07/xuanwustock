# Change: 完整股票发现数据就绪

## Why

股票发现当前仍存在两个不完整点：

- AI Scanner 全量测试会在单元测试路径触发真实历史行情回源，导致排序不稳定和测试失败。
- 发现候选的 `ready` 口径仍偏技术快照字段，stale 快照在部分评分路径里只是扣分，而不是阻止评分。

用户需要股票发现产出的是可被量化生命周期可靠消费的候选，而不是只有展示文本或部分字段的候选。

## What Changes

- 明确发现候选进入量化评分前必须有完整且未过期的核心行情/技术快照。
- 核心行情/技术快照缺失、失败或 stale 时，系统不得计算 `candidate_score` / `candidate_confidence`。
- 自动入池只比较数据 ready 后的技术分和技术置信度阈值；发现来源、策略来源、source score、source confidence 不参与放宽或收紧。
- AI Scanner 单元测试必须隔离外部行情 IO，并保证候选排序稳定。

## Scope

- 股票发现 AI Scanner 行为和测试隔离。
- 发现候选 prepared evidence / data readiness 语义。
- 生命周期 entry gate 与技术评分内核前置校验。
- Discover API/UI 现有诊断字段的口径一致性。
- 后端测试、必要前端测试、真实 API 验证和覆盖证据。

## Out of Scope

- 不调整买卖信号融合算法。
- 不调整资金槽、lot、slot 或仓位执行逻辑。
- 不调整回放收益策略参数。
- 不引入新数据源或新外部依赖。
- 不删除或迁移旧业务数据。

## Impact

- 缺失或 stale 核心行情/技术快照的候选会从“可打低分”变成“不可评分/不可自动入池”。
- 全量测试应不再因 AI Scanner 单元测试触发外部行情 IO 而失败。
- 某些历史 fixture 需要补充或调整 readiness 诊断断言。

## Rules Applied

- `PIR-001`: 后续设计和任务必须列出代码路径。
- `PIR-002`: 修改文件需控制在 1000 行以内。
- `PIR-004`: API 字段语义变化需要记录为兼容的响应语义。
- `PIR-005`: 股票发现仍通过异步任务执行耗时外部 IO。
- `PY-005`, `PY-007`: 外部 IO 必须显式、可诊断，测试不能无意触发真实网络。
- `TEST-001`, `TEST-002`, `TEST-003`, `TEST-008`: 覆盖率、独立测试参数、有效断言、外部 IO 隔离。

## Risks

- ready 口径收紧后，自动入池数量可能下降。
- 如果 freshness 规则以后扩大到交易日语义，可能需要单独变更。
- 现有 source-family gate 逻辑与用户最新口径冲突，需在本变更中去除自动入池的来源差异。

## Open Questions

- 本变更先使用现有核心行情/技术快照字段集，不额外把涨跌幅、换手率、开高低、昨收纳入硬 ready 字段。若后续用户要求，可单独扩展。
- 基础资料字段如总市值、PE、PB 暂作为诊断/展示数据，不作为技术评分内核硬输入。
